# Engineering-expansion traceability matrix (pre-implementation)

**Mission baseline:** authorized branch `arena/5957b76d-prog-proc`; local/remote tip `d4b2fc4256b7107ae1c857e64eb871d3dec50b7c`; `main` observed at `85122e1a98087db4495b820a9a0ffae9009b7819`; only pre-existing local difference is the protected, unstaged deletion `out/performance.json`. No implementation changes have been made at the time of this matrix.

This matrix is based on source, test, configuration, UI, migration, workflow, and current-facing documentation inspection. Earlier mission reports are historical pointers only; their claims are not accepted as this mission's proof.

| ID / acceptance | Verified repository evidence and present gap | Planned implementation and proof |
|---|---|---|
| M-01 MinerU transport choice is truthful; auto avoids redundant HTTP when CLI works; explicit modes isolated | `MinerUProber._probe()` short-circuits to CLI, but `MinerUExtractor.extract()` then calls `MinerUClient.parse()` independently. `parse(auto)` checks OpenAPI even if the CLI is already selected. The existing “auto prefers” test covers only the prober, not the adapter/client call path. | Pass the already resolved prober mode into the client and use one resolver for direct client calls. Add call-count tests proving CLI success causes zero HTTP calls and explicit CLI/HTTP never falls back. |
| M-02 Legacy HTTP is the supported multipart + JSON contract only | `legacy_http_parse_contract()` currently checks only for any response media type containing “json”; it does not verify a multipart request or a successful response's expected JSON envelope. `_parse_http()` takes the first result, permissively coerces content, and does not select/validate the named file. ## Explicit non-claims carried into implementation

OCR accuracy, physical Windows acceptance, PostgreSQL, M2–M5, O-02/O-03, authentication/multi-user, risk/AFE/currency, production DR, encrypted enterprise archive, public deployment, and unsupported engineering inference remain unqualified or owner-gated without new approved evidence. Synthetic fixture metrics and stand-in tests are not OCR accuracy evidence. Qt offscreen is not physical Windows display acceptance. A code/test result is not an exact-SHA CI result until the remote workflow completes for that SHA.
