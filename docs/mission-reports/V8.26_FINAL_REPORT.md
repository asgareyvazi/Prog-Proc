## 1. فاز 1 — تعمیر Fail-Closed در `tools/qt_coverage_gate.py`

**وظیفه:** `main()` باید روی هر خطای الزامی `return 1` کند، `::error::` منتشر کند، `qt_coverage_gate: FAIL` بگوید و هرگز `PASS`/`warning` را جایگزین نکند؛ بدون `|| true`/`continue-on-error`/`sys.exit(0)`.

**یافته:**
```python
# قبل (6375f1b/363de9f — advisory):
if errs:
    for e in errs:
        print(f"::warning::{e}")
    print("qt_coverage_gate: ADVISORY FAIL")
    return 0  # سبز کاذب

# بعد (6fc670d):
if errs:
    for e in errs:
        print(f"::error::{e}", file=sys.stderr)
    print("qt_coverage_gate: FAIL", file=sys.stderr)
    return 1
```

همچنین `expected_sha` نادرست، عدم تطابق SHA با git HEAD، و `git rev-parse` ناموفق همگی `::error::` + `return 1` شدند.

CI: `ci.yml` گام `Qt/UI coverage gate` با `set -euo pipefail` و بدون `continue-on-error`/`|| true`:
```yaml
- name: Qt/UI coverage gate (70% lines, 40% branches)
  if: always()
  run: |
    set -euo pipefail
    python tools/qt_coverage_gate.py --xml coverage-ui.xml --view coverage-ui-view.json --junit pytest-ui-junit.xml --expected-sha "${{ github.sha }}"
```

## 8. فاز 8 — آستانه سخت 70/40 + advisory 71/42

- **سخت:** `line_percent <70` یا `branch_percent <40` → `15: qt/ui ... below 70/40` + `return 1` + `::error::`
- **مشاوره‌ای:** `main()` پس از PASS، اگر `lp<71` یا `bp<42` باشد `::warning::coverage-resilience` می‌دهد ولی PASS باقی می‌ماند:
```python
if lp < 71:
    print("::warning::coverage-resilience: qt/ui line ... below 71%", file=sys.stderr)
if bp < 42:
    ...
if lp >= 71 and bp >= 42:
    print("::notice::coverage-resilience: PASS ... 71/42")
else:
    print("::notice::coverage-resilience: ADVISORY ... below 71/42")
```
تست `test_threshold_boundaries` اکنون `assert "15a" not in ...` و `assert "15:" not in ...` برای 70/40 دارد؛ 71/42 دیگر `15a` error نیست.
