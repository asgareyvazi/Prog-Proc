## 4. The Windows shutdown: the mechanism, corrected

The V8.16 report attributed the native access violation to "the Python
interpreter finalizer". **That label is wrong**, and ADR-61 corrects it:

* CPython's `os._exit` is the CRT `_exit`. On Windows that calls
  `ExitProcess`. **No Python interpreter finalization happens on that path.**
* `ExitProcess` notifies every loaded DLL with `DLL_PROCESS_DETACH` while the
  other threads are still running — here, the GUI thread inside a Python
  callback (`_AcceptQuit.eventFilter`), with the `QApplication`, the PySide6 /
  shiboken bindings and Qt's own static destructors still alive.
* `TerminateProcess` notifies no library, which is the mechanism the fix uses.

The **observation** is not withdrawn: at least ten faults in fifty attempts at
`eab9323`, with frames inside the DLL-detach teardown. After the fix, zero
faults in the same fifty attempts at `2827073`. The correction is additive in
ADR-61, in `docs/WINDOWS_TESTING.md` (two notes) and in both end-to-end
reports; the paragraph it corrects is still there.

Distinguished, because collapsing them is how the wrong fix was chosen the
first time: Python interpreter finalization, CRT `_exit`/`_Exit`, Win32
`ExitProcess`, DLL `DLL_PROCESS_DETACH`, native C++ static destruction,
Qt/PySide6/shiboken teardown, a fault on a thread already inside a Python
callback, and a stack dump that merely shows another thread.

## 5. The termination contract, and what a refusal means

`ui/lifetime.py` has one termination kernel and an **injectable** adapter, so
no test kills a real process inside the pytest process.

| Path | Behaviour |
| --- | --- |
| success | the contracted exit code, once |
| retryable refusal | reported as retryable; the caller may try again; **never** reported as success |
| permanent refusal | reported loudly; **never** success |
| native exception | caught at the boundary and reported with the error code |
| wrong native return type | refused: a non-integer is not a result |
| error-code preservation | the raw code survives to the diagnostic, decimal and hex |
| deadline expiry | the deadline is bounded and documented; there is no unbounded wait |
| watchdog | delegated, and the delegation is recorded |

`is_fail_closed_shutdown_exit` accepts the integer `4` and **nothing else**. It
rejects `3221225477`, `-1073741819`, `True`, `0` and every other non-contract
result, and that is tested. There is no `os._exit` fallback on Windows; POSIX
keeps `os._exit(code)`, which is the documented platform behaviour.

## 6. The stress diagnostics

Every attempt is recorded — mode, ordinal, raw exit code in decimal and hex,
duration, phase markers, the frames of the faulting thread, the terminal-owner
markers, the failure reason, the runtime versions and the log path. The JSON
summary carries **disjoint, exhaustive** counts: attempts, contracted exit,
native access violations, other incorrect exits, timeouts, double terminal
ownership, incomplete transcripts.

The counts are in the summary, not in the annotation limit: GitHub truncates
annotations, so "no annotation" is never read as "no failure". The summary and
the logs are uploaded whether the step passes or fails, and `if: always()`
means a faulted UI suite still gets its measurement.

The step is **gated**. It was not, while the defect was open — a fault that
fires in a few percent of attempts turns a required job into a coin toss — and
`docs/WINDOWS_TESTING.md` said so; that paragraph now carries a correction. A
recurrence is a regression of a closed defect and fails the job.

exits, 0 timeouts, 0 double terminal ownership, 0 incomplete transcripts; step

## 7. The flaky workbench test

Evidence before the fix, because a flaky test that is "fixed" without a cause
is a test that was weakened:

1. 25 isolated runs of the failing node in fresh processes: **25/25 green**.
2. 16 full-suite runs: green. It was not a load race.
3. The session-scoped `qt_app` fixture was the common factor: six tests closed
   their window without releasing the top-level widget, so session-end teardown
   destroyed a `QApplication` that still owned live widgets.

The fix is `release_top_level_widgets(qt_app)` in those six tests plus a
fixture assertion that no top-level widget survives a test — no sleep, no
retry, no weakened assertion. A 25-attempt probe after the fix was **25/25
green**. ADR-62 records the cause; ADR-56 and ADR-60 carry dated corrections.
