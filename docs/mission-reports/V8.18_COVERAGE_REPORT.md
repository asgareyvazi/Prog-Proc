> | **Unmeasured optional runtime** | “not measured” — the runtime was absent, so the group was not exercised | `view["optional_dependencies"]` where `present == false`; rendered as “— (not measured)” rather than “100%” |

## 3. What changed in V8.18

1. **`tools/coverage_report.py`:**
   - Added `_format_percent(total)` so a group with `0` statements renders as
     `— (not measured)` instead of `100%`. The underlying `line_percent` stays
     `100.0` for an empty group (division-by-zero guard), but the report
     qualifies it.
   - Added a terminology banner to the markdown output that defines the four
     metrics and points out the historical 14.39% vs 47% misreading.
   - Changed the CLI one-liner from `80.00% lines` to
     `— (not measured) lines` when the group had no statements, so a headless
     log does not say “qt/ui: 100% lines”.
   - The per-group JSON (`coverage-view.json`) still carries the numeric
     `line_percent` and the `statements` count, so a consumer that needs the
     raw numbers can read them; the qualification is in the presentation.

2. **`.github/workflows/ci.yml`:**
   - `Record the coverage baseline` now emits `coverage-full-suite` and
     `coverage-ui-package` notices in addition to `coverage-total`, and qualifies
     the headless `qt/ui` row as “not measured” in the step summary.
   - `Record the Qt layer coverage` now runs `tools/coverage_report.py` on
     `coverage-ui.xml`, publishes `coverage-ui-report.md`/`-view.json`/`-report.txt`,
     appends the per-group table to the step summary, and emits
     `coverage-ui-total` (whole-source during UI run) **and**
     `coverage-ui-package` (ui package alone) as two separate notices.

3. **This document** replaces the previous misreading with a dated correction
   that preserves the historical baseline and names the three metrics.

No threshold was introduced and no file was excluded from the measurement.

## 4. Definitions (for the next report)

- **Overall line coverage:** `covered_statements / statements` over all files that
  the XML names under `src/drilling_intelligence/`.
- **Overall branch coverage:** `covered_branches / branches` over the same files;
  `0` branches is “not measured” for that file, not “100% uncovered”.
- **Combined coverage:** not used as a gate in this repository; when shown it is
  `(line% + branch%) / 2` with the same source file set.
- **UI-test-run whole-source coverage:** `coverage report --format=total` measured
  while `tests/ui` ran; it covers every source file that `tests/ui` happened to
  import, so a headless file that `tests/ui` never imports still counts as 0.
- **`qt/ui` package coverage:** `view["groups"]["qt/ui"]` (`line_percent` and
  `branch_percent`) from `coverage-ui.xml` — the only number that answers
  “how much of the Qt layer was exercised”.
- **Headless baseline:** a measurement taken without `PySide6`; the `qt/ui` row
  is “not measured” rather than “0% uncovered” and the optional-dependency
  table says `ui: absent`.
- **Unmeasured optional runtime:** the dependency probe says “absent” and the
  group’s statements are `0`; it is not the same as `0%` with `N > 0`.

Future reports must state — for each XML — the commit SHA, the workflow run &
job, the Python version, whether `PySide6`/`mineru`/`ollama` were present, and
the exact XML path (`coverage.xml` vs `coverage-ui.xml`).
