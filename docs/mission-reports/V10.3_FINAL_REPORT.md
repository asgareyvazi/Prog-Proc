## اصلاح‌های نهایی و علت‌یابی

1. **Run card / PowerShell exit code.** در اجرای تشخیصی `612ba14`، transcript نشان داد که همهٔ assertionهای PowerShell 5.1 PASS بودند اما job با exit code 1 تمام شد. آخرین native child عمداً exit غیرصفر داشت و harness همان مقدار خودکار `$LASTEXITCODE` را پس از موفقیت assertionها به فرایند test script نشت می‌داد. در `de2bce3` فقط پس از عبور همهٔ assertionها `$global:LASTEXITCODE` صفر می‌شود؛ هیچ assertion یا مورد ردشده‌ای حذف نشده است. اجرای `41287612975` سپس هر دو PowerShell 5.1 و 7 را PASS کرد و اجرای نهایی `41288046696` نیز هر دو را روی SHA `7f89ae4` PASS کرد.
2. **Intake worker در آزمون UI.** اجرای تشخیصی `de2bce3` خطای bounded deadline در `test_intake_page_uses_worker_and_renders_persisted_queue` را نشان داد. آزمون از `QSignalSpy.wait()` استفاده می‌کرد؛ انتظار به یک `QEventLoop` همراه `QTimer` تک‌مرحله‌ای و deadlineهای موجود 15s/10s تغییر کرد. نه deadline افزایش یافت، نه sleep/ retry یا skip اضافه شد. سپس آزمون کامل offscreen Linux و Windows روی `7f89ae4` سبز شد؛ Windows گزارش 23/23 passed داد.
3. **قرارداد fallback در `result.json`.** `New-MinimalResult` اکنون همهٔ کلیدهای evidence لازم را دارد و template معتبر مستقیماً استفاده می‌شود. آزمون‌های invalid-template، interpreter غایب، دو run ایزوله و مسیر result غیرقابل‌ساخت همچنان fail-closed و فعال‌اند؛ transcript هر دو PowerShell این موارد را PASS گزارش می‌کند.
