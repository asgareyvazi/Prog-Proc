The audit started from the repository state, not the V2 report. The authoritative layers are the static
`DocumentClassification` enum, `classification/taxonomy.py`, stored `Extraction` payloads, Alembic/schema
models, existing repositories/services, tests and executable CLI behaviour. Filenames, folders, prose,
classifier scores, search results and model vocabulary do not authorize promotion.

## C — Classification census

The enum contains exactly **26** classes. The static registry contains exactly **26** contracts:
**5** domain handlers, **4** end-to-end-certified classes, **1** restricted-but-not-certified class,
**16** knowledge-supported denials and **5** extract-only denials. The import-time completeness guard

## D — Deterministic contracts

The V2 IDs for `DRILLING_PROGRAM`, `DDR`, `NPT` and `TIME_BREAKDOWN` remain unchanged. V3 adds only:

```text
document:MUD_REPORT:promotion:v3
```

The handler is the named `mud_report` method. No plugin registry, arbitrary callable, generic domain
writer or classification-to-table fallback was introduced.

## E — Extraction artefacts

Promotion reads the stored extraction artefact linked to the selected `DocumentVersion`. Forced
reprocessing retains prior immutable extraction artefact rows and republishes the cache pointer; the
promoter selects the newest artefact for a version deterministically by `created_at`, then `id`. It no
longer assumes one `Extraction` row per version and no longer raises `MultipleResultsFound` during safe
reprocessing. Source versions remain content-addressed and immutable; unchanged bytes do not fabricate a
new `DocumentVersion`.

## F — Forensic corpus

The V3 corpus is deterministic and contains **12 source-shaped cases**: four admitted cases (program,
DDR, NPT, mud), two existing evidence/degraded cases (lesson, scan), and six explicit unsupported
secondary-domain cases (BHA, bit, directional survey, casing, well control, service). It is generated by
`tests.fixtures.generate.build_v3_forensic_corpus` and validated by
`tests/integration/test_v3_forensic_corpus.py`. The 12-case run classified all files exactly and produced
four promotions plus eight explicit unsupported outcomes; it did not increase support coverage for the
six secondary classes.

## G — Governance, planned and actual

Planned program targets remain planned. Actual section measurements remain actual. Mud source rows use
`record_state=ACTUAL` and never inherit a plan. Human confirmation is a separate lifecycle state from
source status, document approval and `is_current`.

## H — Human confirmation

Admitted mud rows start as `CANDIDATE`. `OperationsRepository.set_status` is the existing actor-bearing
confirmation boundary and is exposed to review/CLI. During source replacement, a confirmed historical
measurement is marked non-current but remains `CONFIRMED`, with its original source version, value and
provenance intact. It is not overwritten, deleted or silently reclassified.

## I — Identity and idempotence

Mud parent/child identities contain source version, table identity, row identity, well and property/sample
identity. Re-running the same version is unchanged; a changed source hash creates a new version and new
source-owned rows. Unstated source rows are removed only when they are unconfirmed; confirmed rows are
retained as historical evidence and marked `source_removed` where applicable. Existing report/program/NPT
identity contracts remain in force.

## J — Joins, scope and section semantics

A linked well is mandatory. If a source names a well or field, it must match the authoritative linked
well/field or promotion returns `WELL_SCOPE_CONFLICT`. Mud section matching is ordered: explicit section
identifier/name first, then deterministic hole-size attributes. Multiple matches remain ambiguous with
`section_id=NULL`; no filename, row position, nearest depth, MD/TVD proximity or UI selection is used.
Absent section evidence remains NULL with an explicit resolution attribute.

## K — Knowledge and graph boundary

The existing knowledge/evidence boundaries remain authoritative. The mud writer adds only justified
source-owned graph edges: `well -> mud_report`, and `well_section -> mud_report` only when the section
was explicitly/deterministically matched. No speculative edges, domain/plugin graph framework or duplicate
review state was added.

## L — Lifecycle and replacement

`MudReport.is_current` and `MudMeasurement.is_current` express source-owned current/history. A newer
version supersedes older derived rows without destroying source history. `status` expresses candidate,
confirmed or rejected human lifecycle; it is not overloaded to mean current. Current CLI/list, review,
search and intelligence views use the explicit current/history policy.

## M — Mud V3 admission

The admitted shape is deliberately narrow: a summary label/value/unit/remark table plus a repeated
sample-labelled daily-test table. Values preserve source text and source unit. Unknown labels, formulas,
unitless/unverified values and non-sample aggregate rows remain in the stored extraction rather than
becoming guessed measurements. No conversion contract was introduced; normalized fields stay NULL.

## N — NPT and calculation safety

The NPT V1 roll-up remains the only executable calculation. V3 does not add mud arithmetic, trajectory
calculation, hidden numeric engines, AI authority or recalculation during ingestion, promotion, indexing,
review, search or pattern staleness. Field intelligence uses grouped SQL for NPT/problem/event/mud counts
and does not materialize all rows merely to aggregate them.

## O — Outcomes and observability

Promotion reports exclusive version outcomes: `ELIGIBLE`, `PROMOTED`, `UNCHANGED`, `UNSUPPORTED`,
`AMBIGUOUS`, `MISSING_ARTEFACT`, `MISSING_WELL`, `MISSING_PROVENANCE`, `INVALID_FIELDS`, `CONFLICT` and
`ERROR`. The forensic `--include-unsupported` mode reports static denials instead of omitting them.
Skip details, contract IDs and per-table created/unchanged/conflict counts remain in CLI JSON.

## P — Provenance

Every admitted parent/child value carries stored table/cell/row context where available, source hash,
document ID, document version ID, relative path and raw source label/value/unit. Retrieval/evidence/search
preserve those citations. Citation auditing distinguishes a source-file hash check from an excerpt check;
structured rendered views are not falsely called broken excerpts.

## Q — Quality and units

Stored quality states remain explicit. Mud `value` is numeric only when the source cell is deterministically
numeric; `unit` is the source unit. A missing unit is `UNVERIFIED`; no unsupported conversion is applied.
Depth, mud properties and sample measurements keep source units and raw wording.

## R — Review

`DomainReviewService` exposes current/history mud parents and nested measurement data in the existing
read-only review contract. `review/actions.py` admits mud parent and child rows to the existing
confirmation lifecycle through `OperationsRepository`; no parallel review persistence was created.
Review does not promote, recalculate or silently confirm.

## S — Search and evidence

Structured search already projects authoritative rows as disposable units. V3 includes mud reports and
batch-reads their measurements. Retrieval re-reads authoritative `MudReport` rows and child values in
bounded queries; evidence packages are built only from retrieval. Search cannot write authoritative state,
and a stale sidecar cannot become evidence merely by being indexed.

## Y — Yield and cleanup

workspaces are created under pytest temp directories and removed by the test harness; no repository
cleanup command was used destructively.
